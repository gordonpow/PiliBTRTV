# 需求：一鍵回報問題（寄到開發者 Gmail）

日期：2026-11-09

## 目標

目前的「回報問題」要用手機掃 QR、同一個 Wi-Fi、再複製或開 GitHub issue，步驟太多，使用者常常給不出完整的回饋。改成在電視上選問題類型後按一下就送出，報告（含 log）自動寄到開發者的 Gmail。

## 使用者決定（2026-11-09）

- 方式：Google Apps Script 網頁應用程式，由開發者用自己的 Google 帳號部署；App 把報告 POST 給腳本，腳本寄信到開發者 Gmail。
- 發布時機：這個功能完成後，與登入修正、UP主頁面、直播閃退修正一起發布。

## 驗收條件

- **AC-1**：「回報問題」對話框第一步列出問題類型：播放卡頓／畫面問題、無法登入、閃退／當機、無法播放、其他。用遙控器選一項並按「送出」即可，不需輸入文字。
- **AC-2**：送出時自動附上現有報告內容（`ErrorReportService.buildReport`：裝置資訊、設定摘要、最近 log、閃退堆疊）。
- **AC-3**：送出成功時顯示「已送出，回報編號 XXXXXX」（6 碼英數字，同一編號也出現在信件主旨中），讓使用者可以告訴開發者。
- **AC-4**：送出失敗（沒有網路、腳本錯誤、超過頻率限制）時顯示原因，並提供「改用手機查看」（現有的 QR 流程）。
- **AC-5**：App 啟動時偵測到上次閃退，跳出的對話框預設選「閃退／當機」。
- **AC-6**：對話框照舊說明會送出哪些資料、不包含帳號、Cookie、登入憑證等。送出的內容與現有報告相同，不另外加入個人資料。
- **AC-7**：開發者收到的信：主旨含回報編號、問題類型、App 版本、裝置型號；內文是摘要；完整報告以 `.txt` 附件附上。
- **AC-8**：腳本端限制：單一報告最大 512 KB；同一裝置（App 產生的隨機安裝 ID）每小時最多 5 封；每日寄信額度不足時回傳錯誤。
- **AC-9**：腳本網址尚未設定（空字串）時，對話框退回現有的手機 QR 流程，不顯示送出按鈕。
- **AC-10**：提供 Apps Script 程式碼與部署步驟文件（繁體中文），開發者照做即可取得網址。
- **AC-11**：`flutter analyze` 沒有新增問題，可以建置。

## 不做的範圍

- 在電視上輸入文字描述（遙控器打字困難）；需要補充時仍可用手機 QR 流程。
- 回覆使用者、工單系統。
- 自動在背景回報（必須使用者主動按送出）。

## 限制

- 腳本網址寫在 APK 內，可能被拆出濫用；以大小、頻率限制與 token 欄位降低風險。
- Apps Script 對 POST 回應 302 轉址；App 端視 200 與 302 皆為已收到，並解析 200 時的 JSON 結果。
- 介面文字繁體中文（台灣用語）。
