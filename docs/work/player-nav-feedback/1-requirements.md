# 播放器導覽與手機回報：需求

使用者請求（2026-11-10）：

1. 循環播放功能，選項比照 PiliBTR。
2. 播放／暫停旁邊加上「上一部」「下一部」。
3. 控制列加彈幕按鈕，短按開關、長按設定。
4. 相關影片改成底部橫排卡片，可往下展開。
5. 可用手機打字回報問題與建議，寄到開發者 Gmail。

取捨已經由使用者用 AskUserQuestion 決定（2026-11-10）：

- 播完行為有 5 種，保留「播完暫停」。
- 上一部／下一部：先看分P，再看播放紀錄。
- 相關影片全部改成底部橫排。
- 使用者確認需求時補充（2026-11-10）：
  - 拿掉「更多影片」按鈕。
  - 番劇播完最後一集時，顯示「已播完最後一集」並直接打開相關影片。
  - 合集也要處理。
- 回報「問題」時附上診斷資料，「建議」不附。

## 目標

讓 TV 使用者不必離開播放畫面，就能控制連播、切換影片、開關彈幕、瀏覽相關影片；也能用手機打字，回報問題或提出建議。

## 名詞

- **下一部**：依序檢查以下條件，第一個成立的就是下一部。
  1. 有下一個分P（番劇是下一集）：播下一個分P。
  2. 影片屬於合集（ugc_season），而且在合集裡有下一部：播合集的下一部。
  3. 不是番劇：播第一個相關影片。
  4. 番劇的最後一集：沒有下一部。
- **上一部**：依序檢查以下條件，第一個成立的就是上一部。
  1. 有上一個分P（番劇是上一集）：播上一個分P。
  2. 影片屬於合集，而且在合集裡有上一部：播合集的上一部。
  3. 播放紀錄裡有前一部：播這次開 App 後在播放器看過的前一部影片。
- **合集順序**：
  - 合集的影片依照 B 站回傳的段落（section）順序和段落內的順序排列。
  - 一部合集影片有多個分P時，先播完它的分P，再播合集的下一部。
- **播放紀錄**：
  - 這次開 App 後，在播放器裡依序看過的影片。
  - 只存在記憶體，關掉 App 就清空。

## 驗收條件

### 1. 播放完畢後的行為

- AC-1.1 「設定 → 播放設定 → 播放完畢後」有 5 個選項，依序是：
  - 播完暫停
  - 直接播下一部
  - 倒數後播下一部（預設）
  - 循環播放此影片
  - 列表循環
- AC-1.2 播放器的設定面板（控制列的「設定」按鈕）主選單多一項「播放完畢後」，可以切換同樣的 5 個選項。改了之後和設定頁同步，並且會保存。
- AC-1.3 各選項播完時的行為：
  - **播完暫停**：停在結尾，顯示控制列。
  - **直接播下一部**：不倒數，直接播下一部。沒有下一部時，照 AC-1.6 處理。
  - **倒數後播下一部**：顯示 UpNextCard 倒數。秒數用「連播倒數」設定。倒數結束後播下一部。沒有下一部時，照 AC-1.6 處理。
  - **循環播放此影片**：從頭重播目前影片。
  - **列表循環**：
    - 有分P、集數或合集時，播下一個；播完最後一個後，回到第一個。
    - 合集影片在整個合集裡循環，分P照合集順序展開。
    - 沒有分P、集數或合集時，重播目前影片。
- AC-1.4 「連播倒數」設定移除 0 秒選項，因為「直接播下一部」已經取代它。
- AC-1.5 舊設定自動轉換成新選項，不需要使用者重新設定：

  | 舊設定 | 新選項 |
  |---|---|
  | 播完暫停 | 播完暫停 |
  | 單個循環 | 循環播放此影片 |
  | 列表循環 | 列表循環 |
  | 順序播放或自動連播，倒數設為 0 秒 | 直接播下一部 |
  | 順序播放或自動連播，倒數大於 0 秒 | 倒數後播下一部 |

- AC-1.6 番劇播完最後一集，而且模式是「直接播下一部」或「倒數後播下一部」時：
  - 顯示提示「已播完最後一集」。
  - 直接打開底部的相關影片（AC-4），不自動播放任何影片。
  - 番劇的相關影片使用番劇的推薦清單。

### 2. 上一部／下一部按鈕

- AC-2.1 控制列底排的按鈕依序是：上一部、播放/暫停、下一部、選集、UP主、彈幕、設定、點讚/投幣/收藏。原本的「更多影片」按鈕移除。
- AC-2.2 按「下一部」立刻播下一部；按「上一部」立刻播上一部。上一部和下一部的定義見「名詞」。
- AC-2.3 沒有上一部時，「上一部」按鈕變暗。沒有下一部時，「下一部」按鈕變暗。變暗的按鈕不會取得焦點，左右鍵移動時會跳過它。
- AC-2.4 「上一部」回到播放紀錄中的前一部影片後，再按「上一部」會繼續往前。

### 3. 彈幕按鈕

- AC-3.1 控制列有一顆彈幕按鈕。圖示會顯示彈幕目前是開啟還是關閉。
- AC-3.2 短按彈幕按鈕會切換彈幕開關，顯示提示「彈幕已開啟」或「彈幕已關閉」，並保存設定。
- AC-3.3 按住確認鍵 0.5 秒以上（長按），會直接打開設定面板的「彈幕設定」子選單。長按不會同時切換開關。

### 4. 相關影片（底部橫排）

- AC-4.1 在控制列按下鍵，畫面底部會出現一排相關影片卡片。卡片樣式和 UP主頁的影片卡片相同：封面在上，下方是標題和 UP 名稱。
- AC-4.2 這一排出現時，影片繼續播放。卡片以外的背景是半透明黑色，透明度比原本右側面板（alpha 0.9）高，可以看到影片的播放狀態。
- AC-4.3 在這一排按下鍵，會往下展開成多排卡片。展開後背景仍然是半透明。
- AC-4.4 在卡片上按確認鍵，會播放那部影片。在第一排按上鍵或按返回鍵，會收起相關影片，回到控制列。
- AC-4.5 原本右側的直式清單移除。

### 5. 用手機回報問題／建議

- AC-5.1 「回報問題/建議」對話框多一個選項「用手機輸入」，選了之後電視顯示 QR 碼和網址。（標籤已改成「回報問題/建議」。）
- AC-5.2 用和電視連同一個 Wi-Fi 的手機掃 QR 碼，會打開一個網頁。網頁可以：
  - 選擇「問題」或「建議」
  - 輸入文字，最多 2000 字
  - 按「送出」
- AC-5.3 送出後，電視透過現有的 Google Apps Script 管道寄到開發者 Gmail：
  - 「問題」：附上使用者輸入的文字和現有的診斷報告。
  - 「建議」：只附上文字、App 版本和裝置型號。
- AC-5.4 送出成功時，手機頁面顯示成功和報告編號，電視顯示提示，並寫入「回報紀錄」。送出失敗時，手機頁面顯示錯誤，使用者輸入的文字仍然留在輸入框，可以再送一次。
- AC-5.5 設定列的說明改為「送出錯誤報告或功能建議給開發者」。
- AC-5.6 手機網頁需要電視產生的一次性 token 才能送出，做法和手機登入相同。沒有 token 或 token 錯誤時，拒絕送出。

## 不做

- 跨 App 重啟保存播放紀錄。
- 手機回報附加圖片或檔案。
- 修改 Google Apps Script 本身。如果它需要改才能區分「建議」，先提出來。

## 限制

- 介面文字只用繁體中文（台灣用語）。
- 遙控器只用方向鍵、確認鍵、返回鍵就要能操作。長按判定比照 `base_tv_card.dart`（500ms）。
- 手機網頁和手機登入共用 LocalServer，不另開 port。
- 回報內容不能含 cookie、token、DedeUserID 等敏感值。
