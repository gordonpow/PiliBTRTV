# 需求：點影片秒開（#58）與播放掉幀（#59）

日期：2026-11-14

## 目標

按下影片卡片到看到第一幀，盡量達到 100～300ms；播放中彈幕捲動、選相關影片時不再肉眼可見掉幀。

## 量測基準（TV 模擬器 Android_TV_API36，btr.24 加計時 log）

- 預設「原生」畫面模式：
  - 移到卡片立刻按 OK：2.7～3.9 秒（videoInfo 0.35～0.57 → 續播進度 0.33～1.1 → playurl 0.4 → initialize 1.1～1.3 → 第一幀）。
  - 停 6 秒（暖機已 ready）再按 OK：6.6 秒。原因：原生模式不接手 textureView 暖機播放器（`player_screen.dart:61`），而且暖機已取走預載的 playurl，播放頁只好重抓。
- 掉幀：`_onPlayerStateChange` 每 100ms 對整頁 setState；彈幕以整數秒同步，每秒集中加入。

## 驗收條件

- AC-1：暖機 ready 後按 OK，原生與相容模式都接手暖機播放器；log `⏱ [E2E] open` 到 `[Startup] shown` ≤ 300ms（模擬器）。
- AC-2：例外：原生模式下暖機串流為 4K（qn ≥ 120）、HDR（125）、杜比視界（126），或直式影片（controller.value.size 高 > 寬）時不接手，改用 platformView 重新準備（保留 Sony 4K 修正與直式綠塊修正）。
- AC-3：沒接手暖機時（例外、暖機未完成、相容模式失敗），播放頁沿用已取得的 videoInfo 與 playurl，不重抓；續播進度查詢與 playurl 並行。
- AC-4：進播放頁的轉場動畫不拖慢出畫面（改為短淡入或無轉場）。
- AC-5：播放中控制列隱藏時，不因位置更新每 100ms 重建整頁；進度相關元件仍正確更新。
- AC-6：彈幕依毫秒位置平均加入，不在整秒時一次塞入。
- AC-7：相關影片列不因位置更新而重建。

## 不做的範圍

- 直播開播速度。
- canvas_danmaku 套件內部改寫（Opacity 層）——僅在不改套件可行時處理。

## 限制

- 不改變設定值與資料格式；「原生」設定仍存在，只影響非暖機的播放。
